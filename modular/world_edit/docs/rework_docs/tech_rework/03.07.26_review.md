## 3. Основные архитектурные проблемы (вероятные в PR #99)

### 3.1 Отсутствие Room Semantic Layer (критично)

Нет промежуточного слоя:

* RoomType (kitchen, dorm, corridor, storage)
* Zone (work area, sleep area, transit area)
* Subzone anchors

➡️ без этого мебель всегда “слепая”

---

### 3.2 Нет “object interaction graph”

Объекты не знают друг о друге:

* стол ≠ центр группы
* стул ≠ привязан к столу
* кровать ≠ часть койко-сета

➡️ результат: случайные конфигурации

---

### 3.3 Нет constraint propagation

Примеры отсутствующих правил:

* “стул только рядом с опорной стороной стола”
* “кровать не ставится в проходной зоне”
* “дверь не должна быть внутри мебельного кластера”
* “рабочие станции требуют свободного радиуса”

---

### 3.4 Wall/door generation не как граф связности

Судя по картам:

* двери не определяют поток
* нет “main path bias”
* комнаты не имеют входной логики

---

### 3.5 Overfill strategy (ошибка плотности)

Похоже есть:

* greedy fill: “заполнить доступные клетки”

Это убивает композицию:

* пространство становится шумом
* исчезают пустоты как дизайн-инструмент

# 8. Solver: как выбирается размещение

Solver делает:

```dm
run_building_semantic_interiors(state)
	build_building_semantic_room_fields(state, result)
	rules = get_building_semantic_scene_catalog(state)

	for(field in room_fields)
		solve_building_semantic_room_scenes(state, result, field, rules)

	emit_building_semantic_solve_result(state, result)
	validate_building_semantic_result(state, result)
```

## Candidate rejection

Scene candidate отклоняется, если:

```text
member turf не в комнате
member turf в door buffer
member turf в primary route
member turf уже занят другой сценой
member требует wall, но wall_dir отсутствует
state.can_place_fixture() = false
scene over_occupancy > max_occupancy_ratio
```

## Candidate scoring

Базово:

```text
+ rule.priority
+ 10000 если required
+ 2500 если primary
+ 900 если anchor == room.focus_turf
+ 120 если corner scene на corner anchor
- 10000 если anchor в door buffer
- 20000 если overlap с occupied/clearance
- 1000 если reserved
```

Этого достаточно, чтобы убрать “равномерный шум” и получить стабильные композиции.

# 9. Emitter: не создаем новый emission path

Сцены эмитятся через существующий `place_fixture_at()`. Это важно: текущий emitter уже пишет metadata для semantic export и report.

Для каждого scene member создается lightweight `cluster_spec`:

```dm
/datum/world_edit_generator/building_layout/proc/build_semantic_credit_cluster_spec(
	datum/world_edit_building_semantic_scene_instance/scene,
	datum/world_edit_building_semantic_member_spec/member_spec
)
	var/datum/world_edit_building_cluster_spec/spec = new

	spec.id = scene.rule.id
	spec.slot = member_spec.slot
	spec.category = member_spec.category
	spec.phase = scene.rule.primary ? "major" : "secondary"
	spec.required = scene.rule.required ? TRUE : FALSE
	spec.pattern = "semantic_scene"
	spec.signature_id = scene.rule.repeat_group
	spec.count_signature_id = scene.rule.repeat_group
	spec.count_cluster_id = scene.rule.id
	spec.semantic_credit = scene.rule.id
	spec.min_count = 1
	spec.max_count = max(length(scene.members), 1)
	spec.priority = scene.rule.priority
	spec.wall_required = member_spec.wall_required || member_spec.wall_mounted

	spec.anchors = list(
		scene.field.zone_id,
		scene.field.room_anchor_id(WORLD_EDIT_SEMANTIC_ANCHOR_CENTER),
		scene.field.room_anchor_id(WORLD_EDIT_SEMANTIC_ANCHOR_WALL_BAND),
		scene.field.room_anchor_id(WORLD_EDIT_SEMANTIC_ANCHOR_SERVICE_WALL)
	)

	return spec
```

Затем:

```dm
place_fixture_at(
```

# 10. Что должно получиться визуально

## Living

Ожидаемая структура:

```text
entry/common zone
  table/living/dining cluster

route/spine
  clear, без мебели

private/service side
  sleeping: bed + cabinet
  sanitation: toilet + sink
  storage/utility: cabinet/rack run
```

Нельзя:

* одиночные стулья без стола;
* кровати в common/storage/sanitation;
* storage scatter по всему полу;
* мебель в door buffer;
* мебель на primary route.

## Dormitory

Ожидаемо:

* bed wall runs / bed niches;
* lockers/cabinets вдоль стены;
* центральный проход чистый;
* optional ready table — только как table+chair scene.

## Storage

Ожидаемо:

* rack/cabinet wall runs;
* crate staging near service/free zone;
* aisle clear from door to back;
* нет шахматной россыпи crates/racks.

## Office

Ожидаемо:

* desk suite;
* chair facing desk;
* filing/cabinet на wall band;
* не больше одного primary desk scene на room.

## Workshop

Ожидаемо:

* workbench/machine wall run;
* rack/storage рядом с service wall;
* optional assembly table в center/free зоне.

## Hydroponics

Ожидаемо:

* tray rows/grid;
* walking aisle;
* seed/tool storage on service wall;
* no tray in door buffer.

# 12. Правила сравнения по visualizer blocks

Визуализатор должен сравнивать не “красивость картинки”, а machine-readable contract:

## Из `semantic.json`

Там уже есть:

* `tiles`
* `rooms`
* `routes`
* `markers`
* `errors`

Каждый tile уже экспортирует flags:

* floor
* wall
* door
* reserved_walk
* blocked
* changed
* error
* objects

Каждый object уже может получить:

* slot
* provider_id
* functional
* category
* zone_id
* anchor_id
* semantic_requirement_id
* dir_source
* wall_dir/front_dir
* wall_mounted

## Следовательно, новые visual assertions должны проверять:

```text
major object without scene id = 0
major object without room/zone = 0
chair without same-scene table = 0
table without same-scene chair = 0
bed outside sleeping/dormitory = 0
toilet outside sanitation = 0
storage outside storage/service except optional = 0
object on reserved_walk = 0
object in door cone = 0
```

Renderer сейчас data-driven: DM владеет генерацией и semantic flags, Python только визуализирует. Это правильное место для сравнения качества без дублирования логики генерации в Python.

# 14. Критерии “готово” по результатам генерации

Работа считается завершенной только если выполняется все:

1. **Все visual cases проходят `expectation_diff = []`.**
2. **Все supported cases имеют `hard_error_count = 0`.**
3. **Для всех major objects есть semantic metadata.**
4. **Нет одиночных furniture atoms без scene/module grouping.**
5. **Все required room roles имеют primary scene.**
6. **Primary route и door buffer чистые.**
7. **Визуально каждая комната имеет читаемую функцию:**

   * living/common — social/dining cluster;
   * sleeping/dorm — bed scene;
   * sanitation — toilet/sink;
   * storage — rack/cabinet/crate run;
   * office — desk suite;
   * workshop — wall bench/storage;
   * hydro — tray rows.
8. **На 10 seeds одного case family инварианты не ломаются.**
9. **Same seed дает тот же `semantic_pattern_signature_hash`.**
10. **Нельзя вручную принимать PNG, если `report.json` не passed.**
