# 2. Почему скрины всё ещё выглядят недоделанными

## 2.1 Один room сейчас получает максимум одну сцену

В `run_building_semantic_interiors()` после первой успешно поставленной scene стоит `break`.

Это приводит к результату:

* common room получает стол + стулья, но не получает side storage / light social props;
* storage room получает 1 rack/cabinet, но не получает staged crates;
* большая комната остаётся слишком пустой.

### Исправление

Нужно разделить сцены по фазам:

```dm
#define WORLD_EDIT_BUILDING_SEMANTIC_PHASE_PRIMARY "primary"
#define WORLD_EDIT_BUILDING_SEMANTIC_PHASE_SECONDARY "secondary"
#define WORLD_EDIT_BUILDING_SEMANTIC_PHASE_DETAIL "detail"
```

Новый цикл:

```dm
var/list/phases = list(
	WORLD_EDIT_BUILDING_SEMANTIC_PHASE_PRIMARY,
	WORLD_EDIT_BUILDING_SEMANTIC_PHASE_SECONDARY,
	WORLD_EDIT_BUILDING_SEMANTIC_PHASE_DETAIL,
)

for(var/phase_id as anything in phases)
	for(var/datum/world_edit_building_semantic_scene_rule/rule as anything in rules)
		if(rule.phase != phase_id)
			continue

		if(rule.primary && placed_primary)
			continue

		if(length(rule.global_limit_id) && rule.global_limit > 0 && (global_scene_counts[rule.global_limit_id] || 0) >= rule.global_limit)
			continue

		var/datum/world_edit_building_semantic_scene_candidate/candidate = select_building_semantic_scene_candidate(state, field, rule)
		if(!istype(candidate))
			if(rule.required)
				required_missing++
			continue

		if(!emit_building_semantic_scene_candidate(state, candidate))
			if(rule.required)
				required_missing++
			continue

		scene_count++

		if(rule.primary)
			placed_primary = TRUE

		if(length(rule.global_limit_id))
			global_scene_counts[rule.global_limit_id] = (global_scene_counts[rule.global_limit_id] || 0) + 1
```

## 2.2 Rule builder слишком рано возвращает `return rules`

Например:

* sanitation сразу возвращает rules;
* sleeping сразу возвращает rules;
* storage сразу возвращает rules;
* common тоже возвращает rules после одной сцены.

Это блокирует вторичные сцены.

### Исправление

Rule builder должен не `return` после primary scene, а добавлять secondary/detail:

```dm
if(building_semantic_room_is_common(room_key, state))
	if(public_focal_count <= 0)
		var/datum/world_edit_building_semantic_scene_rule/common = new("common_primary", WORLD_EDIT_BUILDING_SEMANTIC_SCENE_DINING, WORLD_EDIT_BUILDING_SEMANTIC_PHASE_PRIMARY, TRUE, TRUE, 900, "public_focal", 1)
		common.add_member("table", "table", "dining_focal", "anchor", TRUE, FALSE, TRUE, TRUE)
		common.add_member("chair", "chair", "dining_focal", "adjacent_to_anchor", FALSE, FALSE, TRUE, TRUE)
		common.add_member("chair", "chair", "dining_focal", "adjacent_to_anchor", FALSE, FALSE, TRUE, TRUE)
		rules += common

	var/datum/world_edit_building_semantic_scene_rule/common_side = new("common_side_surface", WORLD_EDIT_BUILDING_SEMANTIC_SCENE_LIVING, WORLD_EDIT_BUILDING_SEMANTIC_PHASE_SECONDARY, FALSE, FALSE, 620)
	common_side.add_member("cabinet", "cabinet", "common_side", "wall_near_anchor", FALSE, TRUE)
	rules += common_side

	return rules
```

## 2.3 Scene rules сейчас слишком string-based

Классификация комнаты идет через `room.role`, `room.zone_id`, `zone_spec.role` и `findtext()`:

```dm
var/room_key = "[role]|[zone_id]|[zone_role]"
if(findtext(room_key, "route") || findtext(room_key, "corridor") ...)
	return rules
```

Это лучше, чем random, но всё ещё недостаточно строго. Например `private`, `living_wing`, `service`, `main` могут случайно попасть не в тот semantic class.

### Исправление

Ввести явный resolver:

```dm
/datum/world_edit_generator/building_layout/proc/resolve_building_semantic_room_class(datum/world_edit_building_layout_state/state, datum/world_edit_building_room/room)
	if(!istype(state) || !istype(room))
		return ""

	var/program_id = "[state.archetype?.id || ""]"
	var/role = lowertext("[room.role]")
	var/zone_id = lowertext("[room.zone_id]")

	switch(program_id)
		if("living")
			switch(role)
				if("entry_common", "dining")
					return "common"
				if("sleeping")
					return "sleeping"
				if("sanitation")
					return "sanitation"
				if("storage", "utility")
					return "storage"

		if("dormitory")
			if(findtext(role, "sleep") || findtext(zone_id, "dorm"))
				return "sleeping"
			if(findtext(role, "locker") || findtext(zone_id, "storage"))
				return "storage"
			if(findtext(role, "ready") || findtext(role, "common"))
				return "common"

		if("storage")
			return "storage"

		if("office")
			if(findtext(role, "storage") || findtext(zone_id, "storage"))
				return "storage"
			return "work"

		if("workshop")
			if(findtext(role, "storage") || findtext(zone_id, "storage"))
				return "storage"
			return "work"

		if("hydroponics")
			if(findtext(role, "storage") || findtext(zone_id, "storage"))
				return "storage"
			return "hydro"

	return ""
```

Дальше rules строить по `room_class`, а не по `findtext(room_key)`.

# 6. Оценка текущих скринов

## Что стало лучше

* Столовые группы уже читаются.
* В некоторых комнатах появилась функциональная специализация.

## Что всё ещё плохо

   * storage/utility/office иногда выглядят как “один объект в комнате”.

3. **Legacy pattern всё ещё просачивается**

   * 3-й скрин с плотной сеткой визуально всё ещё не похож на построенное пространство;
   * это либо старый fixture pass, либо room/zone stage, который генерирует сеточную поверхность без room-level композиции.

4. **Нет гарантии “каждая meaningful room имеет сцену”**

   * по коду это подтверждается: semantic validation считает missing primary scene, но stage не стопорит генерацию.

# 9. Критерий готовности после следующей итерации

Работу можно считать принятой, когда на серии living/dormitory/storage/workshop/hydro/office cases:

```text
semantic_room_primary_scene_missing_count = 0
semantic_major_object_without_scene_count = 0
semantic_pairing_error_count = 0
semantic_scene_route_block_count = 0
legacy_fixture_after_scene_count = 0
semantic_functional_coverage_percent >= 90
semantic_route_clearance_percent = 100
semantic_distribution_noise_score <= 10
```

И визуально:

* каждая большая комната имеет функцию;
* нет одиночных major objects без группы;
* столы всегда со стульями;
* кровати только в sleeping/dorm rooms;
* storage выглядит как wall run / staging, а не как случайные точки;
* коридор и door cones чистые;
* large grid case не выглядит как “объекты на шахматной доске”.
